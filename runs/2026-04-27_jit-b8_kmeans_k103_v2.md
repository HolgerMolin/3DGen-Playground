## Conditioning signal probe — the centerpiece of this run

Two complementary measurements run alongside training:

1. **`[cond]` line (every print, 200 steps)** — `_measure_conditioning_signal` at fixed t=0.3 on a fixed RNG batch. Computes `cfg_signal = ‖pred(y=k) − pred(null)‖_RMS / ‖pred(y=k)‖_RMS` averaged over 16 random classes, and `class_signal = ‖pred(y=a) − pred(y=b)‖_RMS / ½(‖a‖+‖b‖)` averaged over 16 random class pairs.
2. **`cos(c,null)` (every Step print, end of every train batch)** — mean cosine between every learnable class-embedding row and the null-embedding row, taken straight off the embedding table (computed in `train_gsplat.py` at the print site, persisted as `class_null_cos` in `loss_log.csv`).

The first measures *behavior* (does flipping the class change the prediction?); the second measures *embedding-space geometry* (does the class table still occupy a different region than null?).

### Reading the numbers

**(a) `class_signal` is constant at 0.07 across all 100 k steps.** The early v1 number at random init was 0.081 — *higher* than the trained value at step 100 k. The post-resume curve drops to 0.06 around step 5 k, recovers to 0.07 by step 20 k, and stays there. Training has produced no measurable improvement in pairwise class discriminability. At 7 % of the prediction RMS, the model's conditional outputs for class A vs class B are barely more different than they would be if the model emitted random-init class embeddings.

**(b) `cfg_signal < class_signal` consistently.** This is mechanically informative: swapping one conditional class for another changes the output *more* than swapping a conditional for null. That is the geometric signature of class embeddings clustering around (but not exactly at) the null embedding — null is "near the center" of the class cluster, conditionals fall around it on a small sphere, so a-to-b spans ~the diameter of that sphere while c-to-null spans ~the radius. Both scales are tiny (5–8 % of pred RMS), but the ordering tells us where the embeddings live.

**(c) `cos(class_emb, null_emb)` ramps from 0 → 0.57 with no apparent saturation.** This is the most striking single trajectory in the run. At a near-linear rate of ~5×10⁻⁶ per opt step the entire class-embedding table is drifting *toward* the null token. With `null_repel_weight = 0` and `aux_classifier = false`, the only forces on the table are:
   1. The MSE gradient (which has no incentive to keep classes distinct from null — the FM loss only cares about reproducing x₀ given (x_t, t, y); if the trunk has learned to mostly ignore y, then y-table updates contribute negligibly via the chain rule).
   2. CFG dropout (10 % of updates train null-only; the null embedding gets ~1/(num_classes × 0.9) ≈ 100× more updates per row than any conditional row in this regime, so null wanders less while conditionals migrate).
   3. AdamW with wd=0 — no shrinkage pulling rows toward zero.
   With those forces, an embedding table whose rows have nothing pulling them *apart* will diffuse together. That's exactly what the cosine trajectory shows.

**(d) The kmeans-vs-improved-labels comparison.** At step 119 k this run shows `cfg_signal=0.057, class_signal=0.071`. The renderprobe at step 260 k showed `cfg_signal=0.057, class_signal=0.069`. **The numbers are within noise.** Image-kmeans labels are no better (and no worse) than improved text-derived labels for keeping the class signal alive. The label-semantics hypothesis named in `2026-04-21_jit-b8_fullimproved_scaleup.md` — "maybe text-derived labels are too noisy" — is **not supported by this run**: the most-appearance-grounded label scheme available has the same conditioning collapse profile.

### What this run actually measures

Running this experiment was useful even though the conditioning numbers are flat. Three things were resolved:

- **Label semantics is not the bottleneck.** The CLIP-image-kmeans labels are a strict superset of "appearance-grounded" — they *are* the image features, just bucketed. They produced indistinguishable conditioning numbers from text-derived labels. The mechanism keeping `class_signal` flat is upstream of label semantics.
- **The embedding-collapse hypothesis is now backed by direct geometric evidence.** Until this writeup the conversation about cond_signal collapse was about *behavior*. The `cos(c,null) → 0.57` trajectory shows the *cause*: classes are literally migrating to null in embedding space. Any future intervention has to either (i) prevent that migration (`null_repel_weight > 0`, aux head), or (ii) make it irrelevant (replace the LabelEmbedder with a different conditioning channel — e.g. concat-conditioning or a frozen pretrained embedding as in `class_conditioning.md` §"Remaining fixes").
- **Render weight at 0.6 is well-behaved.** No MSE-floor regression vs renderprobe's 6.0; render losses fall about half as fast (matches the sublinear-marginal-utility finding); GN goes to ~0.1 (vs renderprobe's 0.6) and stays there. 0.6 is a defensible operating point for any future run that wants pixel supervision without competing with the trunk.

## Takeaways vs prior runs

1. **Label semantics is not the conditioning bottleneck** — the strongest single result this run produces. Two label schemes a year apart in design (text-derived `improved_labels` vs CLIP-image-kmeans `image_kmeans_k103`) give within-noise identical conditioning numbers on the same trunk, data, and recipe. The scaleup writeup's "labels are partly the issue" hypothesis is at this point falsified for the current LabelEmbedder architecture.

2. **The embedding-table is collapsing toward null in a measurable, monotone way.** `cos(c,null)` going 0 → 0.57 over 100 k steps with `null_repel_weight=0` is the geometric proxy for the behavioral cond-collapse the lineage has been chasing for seven runs. This run is the first one in the writeup history where that geometric signal is clearly tabulated and plotted (`conditioning_combined.png`). Future runs should track this number per checkpoint as a primary target.

3. **The 8-run MSE invariance holds.** MSE = 0.45–0.48 across every full-corpus and aesthetic-corpus permutation, every label scheme, every render weight. P_mean=0.0 + JiT-B/8 + sh_degree0_only is a hard floor on this dataset. **`P_mean_schedule` (the curriculum that has never been tried — already named in `weight_schedule.md` and in the renderprobe takeaways) is the only untried lever for moving the MSE floor.**

4. **Render weight at 0.6 is the right operating point**, given all evidence: (a) renderprobe showed 0.3 → 6.0 buys ~12 % render L1 only; (b) this run shows 0.6 buys *most* of that 12 % at 1/10 the trunk-disturbance risk; (c) GN stays well below the clip ceiling; (d) MSE floor unmoved. Lock 0.6/0.3/0.04 as the lineage default until something else drives a change.

5. **The aux classifier and null-repel rescues, both still untouched**, become higher-priority by elimination. With label semantics ruled out and render saturation mapped, the live "make the class table do something" interventions are: (i) `null_repel_weight > 0` (already plumbed, one number change); (ii) `aux_classifier: true, aux_classifier_weight ~0.01` (requires restart from a no-aux checkpoint with `--aux_classifier` flag, since the head is constructed at model build); (iii) replace LabelEmbedder with concat-conditioning or a frozen pretrained text encoder per `class_conditioning.md` §"Remaining fixes" — high-cost, retrains from scratch.

6. **Per-loss GN probe is now blocking analysis at four consecutive runs.** Without it the "is render at 0.6 still ~50 % of trunk gradient as it was at 6.0?" question cannot be answered. This is plumbing; it needs to be fixed before the next experiment, not after.

## Is scaling the correct next move?

**Still no.** Same answer as the last three writeups, with one new piece of evidence: the new label scheme — designed to be the most appearance-faithful labels in the corpus — produced identical conditioning numbers. JiT-L/8 on this recipe will reach the same `cfg_signal ≈ 0.06` ceiling, just with more parameters. The bottleneck is the conditioning channel, and the conditioning channel is **structurally** broken (embedding collapse), not data-starved or capacity-bound.
